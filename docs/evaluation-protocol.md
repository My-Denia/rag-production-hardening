# Evaluation protocol

## Pre-registration

Selection criteria are frozen in `config/selection_rules.yaml` **before** holdout inspection. M0 records `results/m0_selection_rules.sha256`; M3 fails closed if rules drift mid-run.

## Arms

Exactly 10 arms in `config/arms.yaml`, including:

| Arm | Role |
| --- | --- |
| `hash_dense_k8_r1` | Baseline |
| `recursive_minilm_k8_r1` | Holdout-confirmed winner (this release) |
| `minilm_mq_k8_r1` | Multi-query static synonym axis |
| `minilm_dense_k8_r1_margin` | Margin abstain |
| `retrieval_off_control` | Must score 0 recall / 0 attribution |
| hybrid / BM25 / dense variants | Factor coverage |

Do not add arms post-hoc to chase holdout.

## Splits

| Split | Use |
| --- | --- |
| Dev | Rank and shortlist only |
| Holdout | Confirm primary vs baseline; **no re-rank** |
| Regression-v1 | Immutable dual hit gate (35 labels, all answerable) |

## Metrics

External judge only (see architecture). Canonical selection metric leans on **attribution_rate** and pre-registered significance vs baseline (bootstrap CI excluding zero on recall delta, plus secondary gates).

## Holdout seal

- Direct reads of holdout labels without unlock should fail tests (`tests/test_holdout_seal.py`).
- Unlock env: `RAG_HOLDOUT_UNLOCK=1`.
- Intended production path: `finalize_selection` after `results/dev_shortlist.json`.

## Dual regression gate

Report **both**:

- `recall_hits` / 35
- `attribution_hits` / 35

Recall-only 35/35 is **not** dual success. RCA: `results/regression_rca.json`.

## Forbidden practices

1. Editing gold labels after seeing scores
2. Hardcoding answers for failing qids
3. Dropping hard cases from regression-v1
4. Holdout re-rank / arm shopping
5. Weakening metric definitions silently

## Reporting

Public claims must point at files under `results/` and `docs/public-evidence.md`. Status is regenerated by `run_all` into `docs/status.md`.
